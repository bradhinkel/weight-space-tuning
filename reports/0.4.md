# 0.4 Eval wrappers (BFCL part; ScreenSpot moved to Exp C per the approved reorder)

## What was done
- `common/evals/bfcl.py` runs `vllm serve <ckpt>` (greedy, seed 0, thinking off) and then `bfcl generate` and `bfcl evaluate` from the bfcl-eval venv. It writes `artifacts/bfcl/<tag>/summary.json`.
- `common/evals/bfcl_qwen35.py` registers a `Qwen3.5-local-FC` handler:
  - The prompt is the model's own chat template with BFCL's tools and `enable_thinking=False`.
  - Native XML tool calls are converted to canonical JSON at generation time, typing each value from the entry's own schema.
  - The raw completion is kept in the inference log.
- Categories: `simple_python` (v4 renamed "simple"), `multiple`, `parallel`, `parallel_multiple`, `irrelevance`, `live_simple`, `live_multiple`, `live_irrelevance`.
- **Mean call accuracy** is the unweighted mean of the 6 call categories. **Human confirmed this definition (2026-11-11)** for A.4.
- An audit counter flags raw responses that contain `<tool_call>` but failed to convert. Those would otherwise score as correct abstentions on the irrelevance categories.

## Results
See A.1. The wrapper's checks:
- On a parallel_multiple entry, the rendered prompt contains the tools and ends with the empty think block.
- The converter keeps `"007"` as a string.
- In A.1, 3 of 8,000+ calls failed to convert, all in `live_irrelevance`.

## Surprises or problems
- The stock bfcl-eval `QwenFCHandler` hard-codes Qwen3's JSON template, so it can't be used for Qwen3.5.
- `convert_to_tool` with GORILLA style returned `[]`, which silently dropped every tool. Replaced with BFCL's `_cast_to_openai_type`.
- The first summary had a glob bug: `*_multiple_score.json` also matched `live_multiple`, and `*_irrelevance_` matched `live_irrelevance`. It was caught by checking n (multiple showed 1053 instead of 200, irrelevance 884 instead of 240). Fixed by matching exact file names, then re-collected with `--collect-only`. No regeneration was needed.
