# 0.3 Harness

## What was done
The harness lives in `common/harness/`:

| file | role |
|---|---|
| `mcp_server.py` | MCP stdio server (mcp 2.3 `MCPServer`) exposing exactly `python`, `forward_pass`, `save_weights`, `budget`, `submit` |
| `tools.py` | Harness core: model loading, shared weight buffers, the five tools, test guard, diffs, final checkpoint |
| `kernel.py` | persistent driver kernel (child process) with `W`, a fixed-key name→tensor map over shared memory |
| `sandbox.py` | kernel confinement: unprivileged user + Landlock + seccomp |
| `budget.py` | 1 unit per `forward_pass` call (a batch of ≤ `max_prompts_per_pass` prompts) |
| `guard.py` | sha256 of normalized user messages; test-set guard |
| `logging.py` | JSONL of every call (full args and results), snapshot diffs, summary |
| `driver.py` | launches the locked-down `claude -p` session on the workstation; MCP over SSH to the pod |

Supporting scripts:
- `scripts/lockdown_perms.sh` creates the `wsdriver` user and chmods sensitive paths to 700.
- `exp_a/build_practice.py` writes the practice files and the test guard.
- `scripts/test_harness.py` is a self-test that needs no driver.

**Weights.** All parameters live in one flat buffer per dtype:
- The CPU buffers are shared memory and are what the kernel's `W` edits.
- The GPU model's parameters are views into GPU copies of those buffers. Each `forward_pass` does one host-to-device copy per dtype, so it always runs the current weights.
- An untouched copy of the starting weights backs the diffs.
- `submit` saves the full checkpoint to `/workspace/artifacts/sessions/<sid>/final_checkpoint`.

**Kernel confinement.** Container root can't use namespaces (`unshare` returns EPERM), so three unprivileged layers are used, and the kernel refuses to start if any of them fails:
1. It runs as the unprivileged `wsdriver` user. Artifacts, HF cache, repo, bfcl-venv (which contains the BFCL data), logs and tokens are mode 700.
2. Landlock ABI 4: read-only access to Python, the venv and system libraries; read-write only in the session workdir. `/dev/nvidia*` is not allowlisted.
3. seccomp: `socket(AF_INET|AF_INET6)` and `io_uring_setup` return EACCES.

**Test protection.**
- Only listed practice files are copied into the kernel workdir.
- `forward_pass` refuses any prompt with a user message whose hash is in `test_guard.json`: 2,424 hashes covering every user message in the Exp A test categories. Refused calls are not charged.

**Driver lock-down** (`driver.py`):
- Flags: `--tools ""` (no built-in tools), `--strict-mcp-config`, `--setting-sources local` from an empty cwd under `/tmp` (no user plugins, hooks or CLAUDE.md), `--permission-mode dontAsk`, and `--allowedTools mcp__harness__*`.
- The stream's `init` message is checked, and the session is killed unless the tool list is exactly the 5 harness tools and `harness` is the only MCP server.
- `ANTHROPIC_API_KEY` is stripped from the environment.

## Results
**Self-test** (`scripts/test_harness.py` on 0.8B, `/workspace/artifacts/0.3/harness_selftest.json`): all 11 checks passed. After `TOK` was added on 2026-11-11 (human-approved), the re-run passed 12/12 with `tokenizer_ok`.

**Lock-down dry run** (Opus 5.5): the init tool list was exactly the 5 `mcp__harness__*` tools, `harness` was connected, the model was `claude-opus-5-5`, and `lockdown_ok: true`.

## Surprises or problems
- **mcp 2.x API change.** The installed mcp is 2.3, where FastMCP was renamed `MCPServer`. The first dry run failed (the server never started), and the init check killed the session as designed.
- **Startup time.** The harness takes about 80 s to load 0.8B (CPU and GPU copies plus the kernel). Tools block until it is ready.
- **Design choices (human confirmed 2026-11-11):**
  - One budget unit equals one `forward_pass` call of up to 64 prompts.
  - Generation is capped at 512 new tokens.
  - Attention mode takes at most 8 prompts of ≤ 1,024 tokens.

## Cost
About 0.2 GPU-h for the self-test and dry runs. Two short Opus driver sessions: the dry runs, 2 turns.
