**Disallowed tools refused:**

**Driver's answer (toy task, not evaluated):** of 3 ablated layers, layer 23's MLP changes output length the most. Mean |Δchars| was 168, compared with 102 for L19 and 89 for L22, and it caused repetition loops. It picked the candidates by projecting each MLP's `down_proj` onto the EOS unembedding direction. It reported its own limitations, including one pass wasted on a bug in its own code.

## Surprises or problems
- **No tokenizer in the kernel.** The driver measured length in characters because the kernel had no tokenizer. **Human approved adding one; done:** `TOK` (the target's tokenizer, loaded before confinement) is now in the kernel. The 0.3 self-test was re-run: 12/12 checks passed, including `tokenizer_ok`, and the sandbox still refuses every escape.
- **Wasted passes.** One pass was wasted when a driver ablation didn't apply. That was the driver's own bug, but it suggests a harness note in the task prompt that `forward_pass` runs whatever is in `W` at call time.
- **Fast and cheap.** The session was quick (4.5 min) and small (≈605k tokens, mostly cache reads). A budget-10 session on the 2B should be well within one night's Max usage, but this needs the usage reading to confirm.
