# 0.2 Architecture check

## What was done
`scripts/arch_check.py`, `scripts/vllm_check.py` and `scripts/merge_tiny_lora.py` ran on Qwen3.5-0.8B. Outputs are in `/workspace/artifacts/0.2/` (local copies in `artifacts/pulled/artifacts/0.2/`).

## Results
- **Load class:** `AutoModelForImageTextToText` gives `Qwen3_5ForConditionalGeneration`. The 24 layers repeat the pattern 3× `linear_attention` (Gated DeltaNet) then 1× `full_attention`, so 6 layers are full attention.
- **Language-model linears** (186 in 0.8B):
  - `linear_attn.{in_proj_qkv,in_proj_z,in_proj_a,in_proj_b,out_proj}`
  - `self_attn.{q,k,v,o}_proj`
  - `mlp.{gate,up,down}_proj`
  - `lm_head`
- **Vision encoder:** `model.visual.blocks.N.attn.{qkv,proj}` and `model.visual.blocks.N.mlp.{linear_fc1,linear_fc2}` (48 linears).
- **Vision-to-language merger:** `model.visual.merger.{linear_fc1,linear_fc2}` (needed in C).
- **PEFT LoRA:** 50 steps on 0.8B; the loss fell from 0.3132 to 0.0000.
- **vLLM, base 0.8B:** serves with thinking off. The weather prompt produced a correct native XML tool call and the haiku prompt produced prose. Load took 439.9 s, which includes the first compile.
- **vLLM, merged LoRA:** the 20-step LoRA (`tiny_lora_merged`) loads in 150.6 s and serves. Its output differs from the base model's, so the merge took effect.
- **Tool-call format:** `<tool_call>\n<function=NAME>\n<parameter=K>\nV\n</parameter>\n</function>\n</tool_call>`. Tools are rendered in the system block.
- **Disabling thinking:** `apply_chat_template(..., enable_thinking=False)` pre-fills an empty `<think>\n\n</think>\n\n`.

## Gate status
Not a gate.

## Surprises or problems
- The 50-step LoRA loss went to 0 because the tiny corpus is trivially learnable. The check proves that gradients flow, not that learning is meaningful.
- The merged tiny LoRA answers both test prompts with a repeated `get_weather` call, haiku included. That is the expected effect of the overfit, and it is useful evidence that vLLM is serving the merged weights.
- The tool-call format is XML, not the JSON format Qwen3 used. bfcl-eval has no Qwen3.5 handler, so 0.4 needed a custom one.
- The arch check ran on 0.8B only. Qwen3.5-2B uses the same module names: the trainer's regex matched the 2B in A.2, and vLLM and BFCL served it in A.1.
